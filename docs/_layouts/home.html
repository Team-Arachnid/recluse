Stage 1

Which named attack is this?

A supervised classifier trained on labelled flows. It names the attack families it has seen, and it cannot name one nobody labelled for it.

Stage 2

How unlike normal traffic is this?

An autoencoder trained on benign traffic only. It carries the claim, because it can flag a family that was never in any training set.

Trained on
Benign traffic only
Sees attack labels
Never

How the claim gets tested

Leave-one-attack-out. For each attack family: drop every row of it from supervised training, retrain Stage 1, leave the autoencoder untouched, then score a test set that does contain the family and record what fraction was caught and by which stage. It is what turns the claim from an assertion into a measurement.

Phase 4 produces the table. Until it runs, the claim stays unproven here — see Models and Evaluation for the method and Anti-Patterns for the mistakes that would invalidate it.

The system alerts, ranks and explains. It never blocks traffic.

A false positive from an alerting system costs an analyst minutes. A false positive from a blocking system takes production offline. The constraint is enforced in code: setting IDS_ALLOW_AUTO_BLOCK raises at startup.
